## Where Files Should Live

| Type of file | Location |
|---|---|
| Project documentation & guides | `docs/` |
| Backend NestJS module | `backend/src/<module-name>/` |
| Backend shared utilities | `backend/src/common/` (create if needed) |
| Frontend React component | `frontend/src/components/` |
| Frontend custom hook | `frontend/src/hooks/` |
| Frontend API client functions | `frontend/src/api/` |
| Frontend shared types | `frontend/src/types/` (create if needed) |
| Tauri/Rust desktop logic | `src-tauri/src/` |
| Temporary/scratch files | `/tmp/` (never commit) |

## Rules for Adding New Files

### Backend (NestJS)
1. **One module = one directory.** Each NestJS module gets its own folder under `backend/src/`.
2. **Standard file naming:** `<feature>.module.ts`, `<feature>.service.ts`, `<feature>.controller.ts`.
3. **Register every new module** in `app.module.ts` imports.
4. **Use async I/O.** Never use `fs.readFileSync`, `fs.writeFileSync`, `fs.renameSync`, etc. Use `fs/promises` equivalents.
5. **No hardcoded URLs or model names.** Extract AI endpoints and model names into `ConfigService` or environment variables.

### Frontend (React)
1. **Components live flat** inside `frontend/src/components/`. Do not create nested component subdirectories.
2. **One component per file.** Name the file after the component: `MyComponent.tsx`.
3. **Hooks** go in `frontend/src/hooks/`.
4. **API functions** go in `frontend/src/api/`.
5. **Do not leave dead code.** If a component is replaced, delete the old one immediately.

### Documentation
1. **All `.md` documentation** goes in `docs/`, except `README.md` and `.agent.md` which stay at root.
2. **Never add documentation markdown files** to the repository root.

| Documentation files | `UPPER_SNAKE_CASE.md` | `LAUNCH_GUIDE.md` |

## Guidelines for Safe Refactoring

1. **Always verify builds after moves.** Run `npm run build` in both `backend/` and `frontend/` after any file reorganization.
2. **Update all import paths.** After moving a file, grep the entire project for the old import path and update every reference.
3. **Do not rename NestJS module directories** without also updating the module's `@Module()` decorator and all importing modules.
4. **Prefer incremental changes.** Move one module or component at a time and verify the build after each step.
5. **Delete dead code immediately.** Never leave unused files, imports, or variables behind.

---

## Code Quality Expectations

1. **No synchronous I/O** in any backend service.
2. **No overlapping timers** — use recursive `setTimeout` instead of `setInterval` for polling.
3. **Validate all user-facing input** (URL parameters, request bodies) before using it in file system operations or queries.
4. **Handle errors explicitly.** Every `async` function should have proper `try/catch` blocks or let errors propagate to a global handler.
5. **No hardcoded secrets, ports, or model names** in source code. Use configuration or environment variables.
6. **Keep the `processing` Set or similar lock mechanisms unnecessary** by ensuring polling is strictly sequential (recursive `setTimeout`).
